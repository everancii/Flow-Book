# Phase 04 Plan 01: History-Section Hardening + Cross-Source Verification

**Goal:** Close the one remaining call-site gap (history carousel tap) by copying Phase 3's canonical `_autoPlay` pattern into `history_section.dart`'s `onTap`, then verify nothing regressed — `playback_trust_test.dart` stays green and a manual cross-source smoke (captured as `04-UAT.md`) confirms PLAY-03.

**Scope is deliberately narrow:** one production file is modified (`history_section.dart`); the rest is verification + a UAT artifact. `mini_audio_player.dart` is explicitly NOT modified (D-05).

## Context for the Executor

- **Phase 3** landed the ready-before-play gate in `MyAudioHandler.initSongs` (await `ProcessingState.ready` with a 10s timeout before `play()`). This made the `initSongs(...)` call awaitable — and any caller that does NOT `await` it + catch errors now has a regression surface (a timeout or `setAudioSources` failure is thrown by the handler and bubbles up uncaught).
- Phase 3 hardened three call sites (`_playChapter`, `_autoPlay`, big play button in `audiobook_details.dart`). One call site was missed: the **home history carousel tap** in `history_section.dart` (lines 155-180 today). This phase closes that gap.
- The canonical catch block to copy lives at `audiobook_details.dart:83-91` (and the near-identical `_autoPlay` version at `:131-138`). Read it before editing.
- The race the hardening must NOT introduce: `MiniAudioPlayer.didChangeDependencies` reads the `playingAudiobookDetailsBox`. All four Hive writes (`audiobook`, `audiobookFiles`, `index`, `position`) MUST complete synchronously BEFORE the `await initSongs(...)`. Today `index` + `position` are written AFTER `initSongs` (lines 176-177) — safe only because there is no `await` yet. Adding `await` requires moving those two writes above it. The comment at `audiobook_details.dart:69-71` documents this invariant; copy the spirit.

## LOCKED Decisions (from 04-CONTEXT.md — implement EXACTLY)

- **D-01:** Wrap the `onTap` body (currently lines 155-180) in an `async` closure, `try/catch`, matching `_autoPlay`. Add `await` to the `initSongs(...)` call.
- **D-02:** Catch block matches `_autoPlay` / `_playChapter` verbatim:
  - `AppLogger.debug('Error resuming audiobook from history: $e');`
  - `if (!mounted) return;`
  - `ScaffoldMessenger.of(context).showSnackBar(const SnackBar(content: Text('Unable to start playback. Please try again.')));`
  - Generic message (same as the other 3 call sites).
- **D-03:** Move the two post-`initSongs` Hive writes (`put('index', hist.index)` + `put('position', hist.position)`) to BEFORE the `await initSongs(...)`, so all four writes land synchronously before any await. `_weSlideController.show()` stays inside the try block AFTER the await.
- **D-04:** `initSongs` keeps the default `playImmediately: true` (the user tapped a book — they want it to play). Do NOT pass `playImmediately: false`.
- **D-05:** `lib/widgets/mini_audio_player.dart` is NOT modified. (Startup restore; already correct.)
- **D-06 / D-07:** PLAY-03 manual smoke is captured as `04-UAT.md` (Task 2). Pass bar = zero regressions in the 4 non-Sound-Books sources + Sound-Books works across all 4 entry points.
